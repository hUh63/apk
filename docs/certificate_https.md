# 证书与 HTTPS 抓包

> HTTPS 解密失败、证书报错？看这一篇就够了。

## 原理简介

ProxyPin 采用 MITM（中间人）方式解密 HTTPS：为每个域名动态签发由内置 CA 签发的证书。因此客户端必须**安装并信任** ProxyPin 的根 CA 证书，否则会出现证书错误或抓不到明文。

## 分平台安装步骤

### Android

1. 打开 ProxyPin → 设置 → HTTPS 抓包，确认开关开启
2. 点击「下载证书」/「导出证书」
3. 打开系统「设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书」，选择下载的证书文件安装
4. 安装后建议重启被抓包的 App

**注意事项**：

- Android 7.0+ 的 App 默认**不信任用户证书**，只有浏览器和部分 App 可以直接抓；要抓其他 App 需要：
  - Root 后把证书装入系统证书目录（部分模块可自动处理）
  - 或使用带 Magisk/Shamiko 证书模块的方案
- 部分厂商系统（如 ColorOS/MIUI）对证书安装有额外限制，安装后需在证书管理里确认已启用

### iOS

1. 开启 HTTPS 抓包后，Safari 访问代理提示页下载描述文件
2. 设置 → 已下载的描述文件 → 安装
3. **关键一步**：设置 → 通用 → 关于本机 → 证书信任设置，对 ProxyPin 根证书开启「完全信任」
4. 配置 WiFi 代理指向 ProxyPin

### Windows / macOS / Linux（桌面端）

1. 首次启动会提示安装根证书，确认安装
2. Windows：证书装入「受信任的根证书颁发机构」
3. macOS：钥匙串中找到 ProxyPin CA，设置「始终信任」
4. 桌面端默认开启系统代理；关闭「系统代理」可改为手动配置

## 常见问题排查

| 现象 | 原因与解决 |
|------|-----------|
| 浏览器提示证书不受信任 | 未安装证书或未开启信任，按上述步骤重装 |
| App 内请求失败但浏览器正常 | App 不信任用户证书（Android 7+），需 Root/系统证书 |
| 抓不到任何请求 | 检查代理是否配置正确、端口是否一致、系统代理开关是否开启 |
| 部分域名抓不到 | 检查域名过滤（白名单/黑名单）设置 |
| 双开应用抓不到 | 分身应用网络栈独立，尝试同时给主/分身配置代理 |
| 固定证书（SSL Pinning）App 失败 | 属于 App 自我保护，普通 MITM 无法解密，需特定绕过手段 |

## 目标为 IP 地址的 HTTPS

部分 App 直连 IP 而不是域名，证书校验会失败（SAN 不含 IP）。ProxyPin 会尽量在证书中包含 IP SAN；如仍失败，属于 App 自身校验策略限制。

## 验证抓包是否成功

打开浏览器访问任意 HTTPS 网站，若 ProxyPin 列表出现对应请求且能查看明文响应，即配置成功。
